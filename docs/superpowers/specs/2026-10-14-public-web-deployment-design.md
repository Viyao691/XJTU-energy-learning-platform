# 储能科研智慧平台公网部署方案 · 4GB 轻量首版

日期：2026-10-14。此文件保留原设计依据。用户已批准并开始实施，DNS已添加；最新实施与上线边界见CURRENT_STATUS.md及同日实施计划，下面的“当前/尚未”描述属于原设计阶段。

## 1. 已确定的目标

- 复用考试大王所在服务器，保持当前 4核4GB，不购买新服务器、不扩容。
- 使用 viyao.cn 的子域名，建议 `energy.viyao.cn`；该名称为设计默认值，尚未添加 DNS。
- 储能知识公开展示，科研功能登录后使用。
- 保留现有完整前端和正式首页风格，首版开放轻量科研；重型 OCR、语音转写等以后开放。
- 当前只设计部署及性能优化方案。方案确认后再编写实施计划、修改应用和准备发布。

## 3. 路线比较与选定方案

| 路线 | 取舍 | 本次选择 |
|---|---|---|
| 4GB 共机、分阶段开放 | 新增轻量 Web/API，SQLite，本地文本解析，远端模型；必须测量峰值并重新规划配额 | 用户已选择 |
| 原机器扩至 8GB | 更多本地解析空间，但仍需控制 OCR 峰值并增加成本 | 后续容量不足时再讨论 |
| 直接照搬旧六容器方案 | 多一套数据库/Redis/worker、重模型及重复网关，当前容量和访问方式均不匹配 | 不采用 |

选定方案的边界：先保证知识展示，再开放轻量科研；完整科研工作区保留，但未开放能力显示真实可用状态。不能用 Mock 代替云模型或 OCR 成功。

## 4. 部署结构与域名

```text
浏览器 → HTTPS → 现有 Caddy（唯一 80/443 入口）
  ├─ viyao.cn         → 考试大王原有 Web → 原 API/数据库
  └─ energy.viyao.cn  → 储能 Web
                         └─ /backend-api/* → 储能 FastAPI
                                              ├─ 独立 SQLite / 文件存储
                                              └─ 远端 LLM / 远端嵌入
```

- 新 Compose 项目建议 `energy-research-web`，目录 `/srv/energy-research-web`；卷、数据库、备份和密钥全部独立。
- 新 Web 通过独立共享入口网络连接既有 Caddy，新 API 仅连接储能内部网络及出站网络；API 不直接发布主机端口。
- 保留 `/backend-api` 接口前缀和现有流式代理，首版不增加第二条直达后端的公开入口；后续只有测出代理瓶颈才调整。
- Caddy 配置新增子域名站点并签发独立证书，先验证配置再 reload；共享网络接入可能需要一次 Caddy 容器重建，实施前确认现状并安排短维护窗口。日常储能发布不重建考试大王。
- A 记录指向与考试大王相同的公网地址；未验证 IPv6 时不添加 AAAA。HTTP 跳转 HTTPS，只开放既有 80/443。
- 使用子域名自己的 Cookie，不设置 `Domain=.viyao.cn`，两个网站首版分别登录。无需增加统一登录系统。
- 上线前核对新增站点的域名接入/备案展示要求及公开素材授权，沿用真实备案信息，不把已有备案记录当作新增站点手续已完成。

## 5. 首版功能范围

| 范围 | 首版行为 |
|---|---|
| 游客公开页面 | 正式首页、储能编年史、已有静态知识、帮助与公开来源资讯；具体公开路由建立白名单 |
| 公开学习材料 | 仅展示人工选定、适合公开的内容；现有个人学习包不自动公开 |
| 登录科研 | 个人论文库、PDF 阅读、原生文本提取、笔记、证据问答、多篇比较、想法及实验设计的文本功能 |
| 轻量科研扩展 | 科研数据的限量表格导入、文本导出；沿用已有成果格式，设置体积与行数上限 |
| 模型 | 服务端统一配置远端 LLM 和远端嵌入；未配置或无预算时明确不可用，不自动改成 Mock |
| 定时功能 | 公共资讯共用采集及缓存；个人订阅/自动日报后续开放，避免一注册就启动批量付费任务 |
| 重型处理 | 本地 OCR/Docling、Whisper、视觉模型安装、音频答辩和整库批量重分析首版关闭 |
| 管理 | 系统密钥、模型地址、备份、清理、诊断及模型安装仅管理员可用；普通用户设置仅影响本人 |

默认保留 30MiB PDF 限制；首版建议原生解析最多 100 页、每人存储 200MiB、单表 5MiB/1万行，均为待实施的初始容量策略。扫描件仍可保存和阅读，但需明确“尚无可用于分析的全文”，不伪造全文证据。

## 6. 账号与数据隔离：科研开放前必须完成

1. 新增独立账号和服务端会话，首版采用邮箱验证码登录；复用考试大王的成熟交互思路和邮件基础设施，分别保存账号、验证码、配置和会话，不共用数据库。增加发码限流、过期、错误次数限制；实际收信是验收项。
2. 新增用户所有权：论文及关联报告/分块/图表、笔记、会话、学习包、数据集、想法、实验设计、竞赛工作、订阅、任务及导出。直接拥有的对象保存 user_id，子对象通过父级校验所有权。
3. 所有读写、PDF/缩略图/下载、搜索检索、任务轮询、删除、导出均先从已认证用户作用域查询。不能只在页面上隐藏按钮。
4. 现有全局 SHA-256/DOI/arXiv 唯一约束改为用户作用域去重；首版不跨用户共享私有论文或返回“其他人已经上传”的提示。
5. 公开内容与私有工作区通过显式公开白名单区分。公网从空业务库开始，只导入选定的公开知识；本地私人 PDF、数据库、笔记、备份和校内会话不随镜像迁移。
6. 平台模型密钥仅管理员配置，浏览器只见配置状态及遮罩。普通用户不能更改全局供应商或模型地址；禁止任意 URL 访问云主机内网/元数据地址。
7. Session Cookie 为 HttpOnly/Secure/host-only；Cookie 写操作校验 CSRF 与精确 Origin。前端路由守卫用于体验，后端授权作为最终边界。

以上 schema 修改均使用 Alembic；同步导出 OpenAPI 和生成前端类型。新网站不直接复用旧全站 Basic Auth。

## 7. 4GB 内存与 CPU 预算

**当前上限不能直接叠加新服务。** 3552MiB 已有容器上限加储能 768MiB 已超过 4GiB，尚未计操作系统。因此在轻量科研上线前，需要取得管理员只读资源数据、代表性考试大王检索/上传峰值，并验证配额是否可重新分配。

下表只是容量成立时的候选预算，未修改考试大王配置，也不是已测得可用值：

| 项目 | 候选内存预算 | 约束 |
|---|---:|---|
| 考试大王 API | 1536MiB | 仅在真实检索/解析峰值有余量时才考虑从 2560 下调 |
| 考试大王 Web | 384MiB | 验证 SSR 和页面切换峰值后再考虑调整 |
| 考试大王 PostgreSQL | 320MiB | 按现有数据与连接负载验证；不更改库或账号 |
| 共用 Caddy | 128MiB | 新域名加入后验证证书、日志和峰值 |
| 储能 Web | 256MiB | standalone，Node heap 初始 160MiB，留出堆外/native 空间 |
| 储能 API（含 SQLite） | 512MiB | 1 个 Uvicorn worker，轻量依赖，无本地模型常驻 |
| 操作系统/Docker 预算 | 640MiB | 测量后调整，不等同于可直接配置的容器限额 |
| 预留 | 320MiB | 请求峰值和文件缓存余量 |
| 合计 | 4096MiB | 包含所有预算；主机 MemTotal 可能小于此值，必须据实重算 |

- 储能 Web/API 的 CPU 上限初始分别 0.25/1 核；考试大王原 API 上限为 2 核。线程数与解析并发同样限量。
- 只有容器限额、整机峰值和剩余内存同时满足时才开放双网站科研。Swap 只可缓解异常，不作为正常推理容量。
- 若考试大王不能安全缩小预算：保持其现有配置，首批只发布 Caddy 可服务的静态知识页；前端完整源码保留，登录科研入口等待容量条件，不能宣称已开通。
- 公开静态交付需要从现有页面生成纯静态版本，只包含所需内容和资产；不假设现有全应用可以直接 `output: export`。
- 本次没有管理员资源读数或压力基线，因此 4GB 双业务容量仍待验证，不承诺人数或吞吐量。

## 8. 性能优化实施范围

### 前端与图片

- 保留已有 standalone 打包，构建在 CI/本机 Linux 容器完成，生产服务器只运行成品。
- 按页面懒加载 Mermaid、数据图表和非首屏装饰，后台标签页暂停非必要动画；冻结首页源文件、素材和已接受的排版不作重设计。
- 编年史/工作区公开图像按显示尺寸生成 WebP/AVIF 和响应式版本，首屏只请求当前场景；原图和来源记录留在原始资料目录。homepage 素材不覆盖，只作 HTTP 传输和缓存优化。
- public 约 228.4MiB 不进入首屏下载目标；先记录实际请求，再优化命中的大图，而非删除所有大资源。
- `/_next/static` 与带内容版本的资产长缓存；未版本化的 public 文件使用 ETag/合理短缓存，不一律 immutable。
- 仅公开静态知识可公共缓存。私有 API/PDF/报告使用 private/no-store，不能把带 Cookie 的响应或论文内容进入公共 CDN。
- 首版使用 Caddy 现有压缩，无需新增 CDN。只有公网带宽/首屏实测成为瓶颈时再启用仅公开资源的 CDN。

### API、模型与数据

- 建立独立 Web 轻量依赖清单/镜像，移除运行时 Torch/Paddle/Docling/Whisper；先审查并延迟重依赖导入，确保禁用的功能不在启动、能力探测或诊断时加载模型。桌面版本依赖与能力保留。
- 远端 EmbeddingProvider 为新增适配，不把当前 Ollama 或 Mock 当成云端可用服务。分块记录嵌入供应商、模型/版本及维度，切换模型时定向重建，复用未变化向量。
- 检索先限制到本人及选定论文，分页/分批读取候选分块，避免每次全表 JSON 向量反序列化；小规模先保留 SQLite，不引入向量库。
- SQLite 使用本地磁盘，计划 WAL、busy_timeout=5000ms、短写事务及必要的 user_id/时间/父对象组合索引；调用模型时不持有写事务。WAL 仍只有一个写入者。
- 开启 WAL 前检查生产 Python 内嵌 SQLite 版本含 WAL-reset 修复（3.51.3+，或官方已修复回移版本），不根据 Python 版本推断 SQLite 版本。保持同步持久化策略，不通过关闭 fsync 换性能。
- 复用单进程 HTTP 连接池；外部请求设超时及并发上限。普通元数据接口不继承 600 秒的模型/解析等待策略。

### 排队与费用

- 全站云模型并发初始 2、单用户 1；本地原生 PDF 解析并发 1。拒绝无限后台线程和无界缓存。
- 耗时操作入已有持久化任务表，返回 task_id，由同一 API 进程的有界执行器处理；这是需要补齐的能力，现有未配 Redis 的 TaskQueue 不自动构成可靠队列。
- 保留恢复/取消，任务带 user_id，队列最多 20 项；满时返回可理解的繁忙状态。付费任务不自动重试，避免重复计费。
- 列表分页默认 20；定时公共资讯只采集一次，错峰和备份执行，个人自动订阅首版不启用。
- 每用户和全站双层预算；请求前预留费用、结束后结算，输出预算按科研任务保留，避免以压缩推理深度作为性能优化。初始全站日/月预算建议沿用 5/50 元作为配置建议，只有预算及密钥实际配置后才开放付费调用。
- 在用户界面明确远端模型的数据处理范围。扫描件不自动发送第三方 OCR；未来开放时另行设计权限、费用和容量。

## 9. 发布、备份及恢复

- 发布使用独立 GitHub 仓库 `Viyao691/XJTU-energy-learning-platform` 与独立 deployment environment、key、服务器入口脚本，不复用考试大王 Web 专用网关发布储能应用。
- 首次使用锁定 Linux runtime 镜像；日常源码/资产可增量发布。依赖变更重新构建 runtime，不依赖非标准工作区或临时安装目录。
- 服务器不执行 Next 编译、模型下载、全量测试；磁盘需容纳当前/回滚镜像、部署临时包、业务数据和备份，并额外预留至少 10GiB。
- 先完成本地受控迁移与隔离验证，再用空公网业务库安装；本机私人数据原位保存。
- SQLite 使用现有在线 backup API 生成一致副本，连同受管文件和清单每日备份、保留 7 份；另保存一份受控异机副本。密钥单独私密备份，不进入业务备份或镜像。
- 回滚记录 Web/API 两个镜像修订、schema 版本和备份点。仅 Web 更新可独立回退；迁移后回退需验证 schema 兼容或维护窗口恢复一致副本，不能只换旧 API 镜像。
- 共享 Caddy 变更保留旧配置，先 validate 再 reload；入口失败恢复原配置，并验证考试大王主站。首次基础设施变更和日常储能发布分别控制范围。

## 10. 实施阶段与成功标准

| 阶段 | 交付 | 只做必要验证 |
|---|---|---|
| 0：容量与公开内容核查 | 当前服务器资源、带宽、磁盘、容器峰值和限额；公开路由/素材清单；决定双业务预算是否成立 | 一次基线记录 + 代表性现有检索/解析峰值 |
| 1：Web 适配 | 账号/会话、所有权迁移、管理员边界、公开白名单和独立空库 | 两用户访问矩阵的受控测试，覆盖直接 ID、PDF、下载、搜索、任务与删除 |
| 2：轻量与优化 | 轻量镜像、远端嵌入、有界任务、缓存及按需加载 | 针对任务恢复、隔离检索和预算的定向测试；一次必要生产构建 |
| 3：预发布 | 独立容器、合成 PDF、测试账号、私密配置和回滚包 | 真实注册收信、登录、上传/文本/问答带引用、退出、跨用户拒绝、重启数据保留；真实模型只作必要样本 |
| 4：接入域名 | DNS、证书、既有网关接入、备案展示 | 公网 HTTPS/证书/跳转及两个站点代表性业务 |
| 5：容量验收 | 记录负载、内存、延迟、队列及冻结修订 | 一次 10 分钟代表性混合负载，不反复跑全套或重截图 |

初始验收目标为待实测指标：

- 在约定客户端、网络和代表知识页上记录冷/热首屏；目标公开知识页 LCP≤2.5秒、初始资源≤1.5MiB。冻结首页单独记录，不通过重设计或虚报达成指标。
- 混合负载初始为 20 个知识浏览会话、5 个登录科研会话；含 1 个原生 PDF 解析及最多 2 个远端模型任务。它是测试场景，不是承诺的持续用户容量。
- 不含外部模型耗时的元数据/列表请求 P95≤800ms，排队任务受理≤2秒；网络和上传传输时间另列。
- 该负载下储能容器合计不突破约 768MiB候选预算、无 OOM/异常重启，主机 available 内存目标≥300MiB；CPU 长时间超 80% 时暂停新后台任务而不是无限排队。
- 考试大王代表性响应 P95 相比同机基线增加不超过 `max(基线的10%, 100ms)`，并保持原检索和上传成功。若未满足，收缩储能并发或回到仅静态知识阶段。
- 重启后任务状态可恢复，重试不重复收费；所有私有对象拒绝跨用户访问；扫描 PDF 不产生虚假的全文报告。
- 一次临时目录恢复演练能读回测试账号和合成论文；记录 RPO≤24小时的备份策略，RTO目标≤1小时，实际以演练结果为准。

## 11. 实施前需要核实的事项

当前没有管理员服务器资源读数、SMTP实收、远端嵌入供应商联通和首屏负载证据；这些事项影响上线条件，不阻止本次方案设计。不得把设计预算当作性能优化已完成。

轻量科研在容量不足时延后，是本方案明确的退路；方案未授权现在改考试大王配额、创建 DNS、设置密钥、执行迁移或替换在线服务。
